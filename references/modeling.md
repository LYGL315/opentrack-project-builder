# OpenTrack 建模参考

## 站场、双顶点与跨图连接

1. 为每站列出上下行进站端、咽喉、正线、到发线、停车点、出站端及区间接口。轨道边记录端点、实际长度、坡度、曲线半径及分列车类别限速。图面可以是示意位置。轨道的运行长度看 Edge Inspector，公里标是定位参考，图面坐标用于绘图。
2. 双顶点的两个半顶点服务于方向和连接关系。对跨工作表边界，检查两端使用预期的空闲半顶点，各方向连接唯一，线路长度和限速在两图接缝处没有重复或缺口。运行时加载所有关联工作表。用上下行单车测试接口，再检查 Route、Path 和 Itinerary 可引用预期的下一张表。
3. 用独立对象记录车站基准点、停车标、道岔、信号或属性变化点。参考图把同一段画成三处或四处双顶点时，核对每个新增点的功能、属性、相邻边长度和进路边界。如果差异只是示意画法，编号或数量可以不同。如果信号、分段限速或停点丢失，修正工程并复跑。连续数个方块也可能是两个相邻双顶点或多个独立对象，逐个用 Inspector 识别。
4. `Functions → Group → Station Area` 可将选中的站场对象归入车站。通常覆盖两端对应的进站边界、站台和咽喉。边界以本模型的信号和站区设计为准，停站列车应完整位于相应站区。检查 `Station Sign` / 所属站标记和停点。站区归属可能影响进路预留时刻，修改后对照正常、追踪、临时限速等受影响场景。

## 顶点、标志与信号

| 图面现象 | 确认方式 |
| --- | --- |
| 深蓝色方块 | 在常见绘制样式中提示车站顶点。检查 Vertex Inspector 的 Station Vertex，以及关联的车站标记。 |
| 浅蓝色方块 | 在已验证的 1.x 工作表中，普通双顶点加入 Station Area 后可能以浅蓝显示。核对所属车站及其他顶点属性。 |
| 粉红或红色方块 | 可提示该顶点定义了至少一个 Route。核对 Route 起点、方向、信号属性及路径列表。定义了 Path 的顶点在常见样式下显示绿色。 |
| 白色或灰白方块 | 常见为未显示前述专用状态的连接顶点。仍需核对顶点的站区、道岔和引用关系。 |
| 像小船的定向标志 | 可对应停车标（halt board / halt point）。在 Inspector 中核对对象、作用方向、列车长度或停点条件，并用实际停车位置验证。 |
| 红绿灯或组合标志 | 在 Signal Inspector 中确认主信号、预告信号、组合信号、朝向及关联。仿真时的灯色和轨道占用颜色属于运行状态。 |

颜色和符号随版本、显示设置及叠加状态变化。遇到图例歧义时，以对象类型、方向、属性及运行证据定案。原生站场图或基于对象清单绘制的示意图都应标明信号功能、停车标、股道编号和跨图指向。

按运行方向规划主信号，核对保护对象和受控进路。进站信号保护进站咽喉与接车进路，出站信号控制列车驶离股道，闭塞信号划分区间追踪边界。预告或组合信号的关联、视距与列车制动能力、来车侧速度及边界条件一起校验。确认下一主信号可获得信息。仿真始发需要的控制点单独标注，保留正式出站信号的角色和位置。

遇到 `No Info for Signal` 或非预期停车，先定位车次、方向、信号编号及上游轨道。检查进路边界、预告关联、接近速度、视距、坡度与车辆制动数据。教学模型可先用 `v²/(2a)` 加响应距离和余量估算检查区间，统一 `v` 为 m/s、`a` 为 m/s²，并按曲线、坡度及模型参数复核。使用原生日志检验估算结果，每个模型自行建立参数依据。

## Route、Path、Itinerary、Course 和 Timetable

| 对象 | 设置逻辑 | 核验方法 |
| --- | --- | --- |
| Route | 由有序顶点描述同方向的移动，在两个主信号之间建立，归起始信号所在顶点。需要时定义道岔分支、进路释放、接续和限速对象。 | 在 Route Inspector 回看顶点、信号端点、方向和释放设置。分别验证直向、侧向和相互冲突的进路。 |
| Path | 组合一个或多个同方向、首尾相接且经常一起使用的 Route。可把对照实验要定位的 Route 保持独立。 | 将 Path 展平为 Route ID 序列。合并前后逐车比较序列、停点、基准日志和到发数据。 |
| Itinerary | 由连续 Path 描述运行径路。全程或局部备选经实际线路和调度需求定义。不同股道径路使用明确的名称。 | 检查始发与终到对象、方向、跨图引用及候选优先级。若需求包含备选径路，构造会触发选择的仿真。 |
| Course | 指定车次、Train、候选 Itinerary 及其优先级。 | 核对车次、候选线路的适用方向和停车条件，在原生输出确认实际选择。 |
| Timetable | 填计划始发、计划到发或通过和最小停时。1.7 发行说明中可见 `Dwell` 替代 `Wait` 的界面用语。 | 按车次与站点比较计划和实际，核对停站标志、天数偏移、终到和股道释放。 |

例如虚构铁路的甲站出站信号、区间闭塞信号、乙站进站信号依次构成两条 Route。可把它们组合为一个同向 Path，并在 Itinerary 串接乙站到发所需 Path。乙站有两条可用到发股道时，给各自的 Route 与候选径路明确命名并核验各自的停点和优先级。

车辆数据先录入 `Engines` 的牵引力—速度节点及其单位，编辑节点时确认选中实际数据点并提交，再在 `Trains` 关联机车、车辆和编组。保存后重新加载，验证编组选中正确的牵引单元。未有权威资料的质量、阻力、制动及牵引数据明确列为教学假设。

产品与数据结构概述见 [OpenTrack Railway Technology](https://www.opentrack.ch/mobile/opentrack_e/opentrack_e.html)。具体界面以所用版本的用户手册、发行说明和本机实际显示为准。
